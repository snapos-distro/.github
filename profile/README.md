## What is SnapOS?

SnapOS is a Linux distribution built on **NixOS**, with an everyday desktop on top.

NixOS describes the whole system in one file and can undo any change, but its
commands are hard for someone coming from Ubuntu or Debian. SnapOS is the bridge:
you keep the habits you already have (search, install, remove, update) under one
command, `snapos`, and SnapOS shows you the NixOS way behind each one.

<p align="center">
  <img src="https://raw.githubusercontent.com/snapos-distro/SnapOS/main/branding/snappy-commands.gif" alt="Snappy maps the apt commands to their snapos equivalents" width="600">
</p>

- **Four desktops:** Budgie, KDE Plasma, Xfce or Hyprland, each in dark or light.
- **Updates that cannot break the system:** a new system is built for the next
  start, and SnapOS goes back by itself if it does not reach the login screen.
- **SnapGuard:** a real-time antivirus based on ClamAV.
- **`.deb` programs:** a native Debian layer, where even Steam runs.
- **x86_64 and ARM64** images, and an installer in English or Portuguese.

## How this organization works

| Repository | What it is |
| --- | --- |
| [**SnapOS**](https://github.com/snapos-distro/SnapOS) | The official repository. It only receives code that already passed every test, and it holds the releases you download. Installed systems update from its latest release. |
| [**snapos-test**](https://github.com/snapos-distro/snapos-test) | The staging repository. New features and fixes are written and tested here first: the ISOs are built and every desktop is booted in a virtual machine on each change. |

```
 snapos-test                                   SnapOS
 write the change ─▶ build + VM tests ─▶ same commit ─▶ draft release ─▶ published
```

A release is never built in the official repository: a short action copies the
tested files from snapos-test, checks their SHA-256 and that they were built from
the very same commit, and creates a draft that is published by hand.
